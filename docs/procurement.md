# Блок `procurement`

Закупівлі: у кого купуємо деталі, що замовили, що з цього вже приїхало. Другий
блок Фази 2. Живе в парі зі `inventory`: склад каже, чого бракує (`stock.low`),
закупівлі відповідають приходом (`purchase.received`).

## Чотири артефакти блоку

| Артефакт | Де лежить | Що це |
|---|---|---|
| Контракт | [`contracts/procurement.yaml`](../contracts/procurement.yaml) | OpenAPI 3.1, публічний інтерфейс |
| Сервіс | [`services/procurement/`](../services/procurement/) | FastAPI + власна схема в PostgreSQL + слухач шини |
| Фронтенд-модуль | [`packages/modules/procurement/`](../packages/modules/procurement/) | замовлення, прихід за накладною, потреби, постачальники |
| Документація | цей файл | статуси, приходи, потреби, межі |

## Що блок віддає

| Метод | Шлях | Право | Що робить |
|---|---|---|---|
| `GET` | `/procurement/suppliers` | `procurement.read` | постачальники: пошук, `archived=true` — з архівними |
| `POST` | `/procurement/suppliers` | `procurement.write` | новий постачальник |
| `GET` / `PATCH` | `/procurement/suppliers/{id}` | read / write | картка; `active: false` — в архів |
| `GET` | `/procurement/orders` | `procurement.read` | замовлення: пошук за номером і постачальником, фільтр статусу |
| `POST` | `/procurement/orders` | `procurement.write` | нова чернетка |
| `GET` / `PATCH` | `/procurement/orders/{id}` | read / write | замовлення; примітка, дата, постачальник (у чернетці) |
| `POST` | `/procurement/orders/{id}/status` | `procurement.write` | відправити, закрити з недопоставкою, скасувати |
| `POST` | `/procurement/orders/{id}/lines` | `procurement.write` + `catalog.read` | додати деталь з прайсу |
| `PATCH` / `DELETE` | `/procurement/orders/{id}/lines/{lineId}` | `procurement.write` | кількість і ціна; прибрати |

| `DELETE` | `/procurement/needs/{partId}` | `procurement.write` | «не замовляти» |

Права: власник і комірник — усе; інші ролі закупівель не бачать.

## Замовлення

| з | у |
|---|---|
| `draft` (чернетка) | `ordered` — є рядки й у кожного вказано ціну; `cancelled` |
| `ordered` (відправлено) | `received` — закрити з недопоставкою, якщо хоч щось приїхало; `cancelled` — якщо нічого |

`received` і `cancelled` — кінцеві. Рядки (деталь, кількість, ціна) змінюються
лише в чернетці: відправлене — це вже домовленість з постачальником. Одна
деталь — один рядок; треба більше — більша кількість.

Номер `PO-2026-00042` — рік за місцевим часом (`BUSINESS_TIMEZONE`) і
порядковий номер, як у нарядів: один `UPDATE … RETURNING` під блокуванням.
Перевірено на PostgreSQL: 20 одночасних створень — 20 різних номерів.

## Прихід

Відправлене замовлення приходить частинами — кожна накладна окремим приходом.
По кожному рядку вказується, скільки приїхало, і, якщо в накладній інша, —
фактична ціна. Більше, ніж лишилось отримати, прийняти не можна. Коли отримано
все, замовлення закривається само.

Замовлення блокується на час приходу (`SELECT … FOR UPDATE`): два комірники,
що одночасно оприбутковують ту саму накладну, не отримають товар двічі.
Перевірено на PostgreSQL: два одночасні приходи по 6 при залишку 10 —
один проходить, другий отримує «лишилось отримати 4».

Після коміту — подія `purchase.received` з рядками приходу. Склад заводить з
кожного партію за ціною з накладної. Id рядка приходу — ключ ідемпотентності:
повтор події партій не подвоює.

## Потреби

```
inventory: вільно < мінімум  ──stock.low──▶  procurement: потреба
                                                 │
                     деталь уже купували? ──так──┼─▶ чернетка тому ж постачальнику
                                                 │   за останньою ціною
                                            ні ──┴─▶ чекає в «Потрібно замовити»,
                                                     поки оберуть постачальника

inventory: прихід ──stock.received (low=false)──▶ потребу закрито
```

- Скільки замовити: щоб вільного стало **два мінімуми** (`2 × мін − вільно`),
  штуки — вгору до цілого. У чернетці кількість можна змінити.
- Одна чернетка на постачальника: нові потреби дописуються в неї — один лист
  постачальнику замість десяти.
- Якщо деталь уже є в чернетці чи в відправленому й ще не отриманому
  замовленні — вдруге не додається.
- Потреба закривається, коли прихід підняв вільний залишок до мінімуму
  (`stock.received` несе `low`), або вручну — «не замовляти» (до наступного
  сигналу складу).
- Подія старша за вже застосовану ігнорується; повтор нічого не змінює.

## Що блок слухає й публікує

| Подія | Напрям | Навіщо |
|---|---|---|
| `stock.low` | слухає від `inventory` | потреба; чернетка, якщо відомий постачальник |
| `stock.received` | слухає від `inventory` | закрити потребу, якщо деталі вже вистачає |
| `purchase.ordered` | публікує | `analytics`; `finance` — майбутній борг перед постачальником |
| `purchase.received` | публікує | `inventory` — партії на склад; `finance` — борг за накладною |

Черга слухача — `procurement.events`. Підтвердження після коміту.

## Запуск

```bash
docker compose up -d postgres rabbitmq
cd services/procurement
cp .env.example .env        # розкоментуйте RABBITMQ_URL — інакше склад не отримає приходів
uv sync --group dev
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8008
```

## Перевірки

```bash
cd services/procurement
uv run pytest         # 12 тестів
uv run ruff check .
uv run mypy app

cd ../..
pnpm --filter @baymeister/module-procurement typecheck
```

Наскрізно зі справжнім RabbitMQ і браузером: постачальник → чернетка → рядок з
прайсу → відправлено → прихід 5 з 12 → на складі 5 шт. за 500 ₴ → закрито з
недопоставкою → мінімум 8 на складі → потреба → чернетка тому ж постачальнику
на 11 шт. (2 × 8 − 5) за останньою ціною.

## Що лишилось зробити

- Замовлення постачальнику через його API чи email — зараз «відправлено»
  ставиться вручну після дзвінка чи листа.
- Друк замовлення й прибуткової накладної — блок `documents`.
- Борг перед постачальником і оплата — блок `finance` (слухає `purchase.received`).
- Повернення постачальнику.
- Подія публікується після коміту без outbox: якщо шина впала саме між комітом і
  публікацією, прихід не дійде до складу — як і в інших блоків, до появи outbox.
