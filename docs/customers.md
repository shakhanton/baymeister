# Блок `customers`

Еталонний блок. Решта блоків копіюють цю структуру.

Клієнти автосервісу: фізичні та юридичні особи, контакти, знижки, архів.

## Чотири артефакти блоку

| Артефакт | Де лежить | Що це |
|---|---|---|
| Контракт | [`contracts/customers.yaml`](../contracts/customers.yaml) | OpenAPI 3.1, публічний інтерфейс |
| Сервіс | [`services/customers/`](../services/customers/) | FastAPI + власна схема в PostgreSQL |
| Фронтенд-модуль | [`packages/modules/customers/`](../packages/modules/customers/) | екрани, маніфест, хуки |
| Документація | цей файл | межі блоку й події |

Усі чотири — в одному володінні. Виконавець блоку не чекає ні на кого.

## Що блок віддає

| Метод | Шлях | Що робить |
|---|---|---|
| `GET` | `/customers` | список із пошуком, фільтром за типом, пагінацією, архівом |
| `POST` | `/customers` | створити |
| `GET` | `/customers/{id}` | один клієнт |
| `PATCH` | `/customers/{id}` | часткове оновлення |
| `POST` | `/customers/{id}/archive` | мʼяке видалення |

Повні схеми — в контракті. Він головніший за код: якщо вони розійшлись,
виправляється код.

## Що блок публікує

| Подія | Коли | Хто слухає і навіщо |
|---|---|---|
| `customer.created` | створено клієнта | `notifications` — вітальне SMS |
| `customer.updated` | змінено дані | `vehicles`, `work-orders` — оновлюють власну копію імені й телефону |
| `customer.archived` | архівовано | `analytics` — виключає з активної бази |

Слухачі мусять обробляти повторну доставку ідемпотентно: брокер гарантує
at-least-once, а не exactly-once.

## Межі

**Блок не зберігає** автомобілі, наряди, платежі. Ці блоки тримають у себе
`customer_id` і власну копію імені з телефоном.

**Дублювання навмисне.** Якби `work-orders` щоразу питав ім'я клієнта в цього
сервісу, кожен список нарядів перетворювався б на віяло запитів. Копія
оновлюється подією, а не запитом на льоту.

**Архівування мʼяке.** Клієнт зникає зі списків, але лишається доступним за
ідентифікатором — наряди й автомобілі на нього посилаються, і обірвати це
посилання не можна.

**Телефон унікальний.** Це природний ключ клієнта в автосервісі: майстер шукає
людину за номером, а не за прізвищем. Спроба створити другого клієнта з тим
самим номером дає 409, а не мовчазний дубль.

## Рішення, які варто скопіювати

**`repository` окремо від `routes`.** Запити до бази тестуються без HTTP,
маршрути не знають про SQL. Розділення на два файли, а не на три шари — більше
для цього обсягу не потрібно.

**Pydantic-схеми як єдине джерело.** Вони ж валідація, вони ж OpenAPI, вони ж
типи для mypy. Дублювати опис полів у трьох місцях не доводиться.

**Zod на фронті дублює обмеження контракту.** Свідомо: користувач бачить помилку
до запиту, а бекенд усе одно валідує ще раз — клієнту довіряти не можна.

**Тести проти ASGI-застосунку, а не проти функцій.** Перевіряється те, що
справді віддає сервіс: коди, тіла, помилки. База — SQLite у памʼяті, тому
`pytest` не потребує ні Docker, ні мережі.

**Помилки — текстом для людини.** Бекенд віддає `{"detail": "Клієнт із
телефоном +380671234567 уже існує"}`, фронт показує саме це, а не «HTTP 409».

## Запуск

```bash
docker compose up -d postgres
cd services/customers
cp .env.example .env
uv sync --group dev
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8001
```

Фронтенд у дев-режимі ходить через проксі Vite: `/api/customers` → `:8001`.
Коли зʼявиться справжній gateway, зміниться один рядок у `vite.config.ts`.

## Перевірки

```bash
cd services/customers
uv run pytest         # 11 тестів
uv run ruff check .
uv run mypy app

cd ../..
pnpm --filter @baymeister/module-customers typecheck
```

## Що лишилось зробити

- Права доступу. Зараз каркас працює під вигаданим власником із правом `*`;
  реальна перевірка `customers.read` запрацює разом із блоком `identity`.
- Історія звернень і сегменти клієнтів — у контракті їх ще немає.
- Обʼєднання дублів: два клієнти з різними номерами, але однією людиною.
