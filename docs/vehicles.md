# Блок `vehicles`

Автомобілі клієнтів: держномер, VIN, марка, модель, рік і історія пробігу.

Перший блок, що **слухає** події: тримає власну копію імені й телефону
власника й оновлює її за `customer.updated`. Зразок для кожного блоку, якому
потрібні чужі дані в списках.

## Чотири артефакти блоку

| Артефакт | Де лежить | Що це |
|---|---|---|
| Контракт | [`contracts/vehicles.yaml`](../contracts/vehicles.yaml) | OpenAPI 3.1, публічний інтерфейс |
| Сервіс | [`services/vehicles/`](../services/vehicles/) | FastAPI + власна схема в PostgreSQL |
| Фронтенд-модуль | [`packages/modules/vehicles/`](../packages/modules/vehicles/) | екрани, маніфест, хуки |
| Документація | цей файл | межі блоку й події |

## Що блок віддає

| Метод | Шлях | Право | Що робить |
|---|---|---|---|
| `GET` | `/vehicles` | `vehicles.read` | список: пошук за номером, VIN, маркою, власником; фільтр за клієнтом; архів |
| `POST` | `/vehicles` | `vehicles.write` | додати; пробіг при прийманні стає першим записом історії |
| `GET` | `/vehicles/{id}` | `vehicles.read` | один автомобіль |
| `PATCH` | `/vehicles/{id}` | `vehicles.write` | змінити; новий `customer_id` — це продаж |
| `POST` | `/vehicles/{id}/archive` | `vehicles.write` | мʼяке видалення |
| `GET` | `/vehicles/{id}/mileage` | `vehicles.read` | історія пробігу, від нових до старих |
| `POST` | `/vehicles/{id}/mileage` | `vehicles.write` | записати показник одометра |

## Звʼязок із `customers`

```
                  POST /vehicles (customer_id)
 Shell ──▶ Gateway ──▶ vehicles ──GET /customers/{id}──▶ customers
                          │        (X-User-* того самого користувача)
                          ▼
             копія: customer_name, customer_phone

 customers ──customer.updated──▶ RabbitMQ ──▶ черга vehicles.customer-events ──▶ vehicles
                                                        оновлює копію в усіх авто клієнта
```

**Синхронно — один раз.** При створенні й продажу сервіс питає `customers`,
чи існує клієнт, і бере імʼя з телефоном. Запит іде від імені того самого
користувача: заголовки `X-User-*` передаються далі, і `customers` сам вирішує,
чи можна цьому користувачу бачити клієнта. Тому для вибору власника потрібне
ще й право `customers.read`.

**Далі — подіями.** Список автомобілів ніколи не ходить у `customers`. Копія
оновлюється за `customer.updated`.

Якщо `customers` недоступний, створити чи продати автомобіль не можна — 503 з
людським поясненням. Решта блоку працює.

## Як обробляються події

`app/consumer.py` — зразок споживача для решти блоків.

- **Власна довговічна черга** `vehicles.customer-events`: поки сервіс лежить,
  події накопичуються й доходять після старту.
- **Підтвердження після коміту.** Сервіс впав посередині — брокер доставить
  повторно.
- **Ідемпотентно й стійко до перестановки.** У кожного авто є
  `customer_synced_at` — час події, з якої взято копію. Подія застосовується,
  лише якщо вона новіша. Повтор тієї самої або запізніла стара нічого не
  змінюють.
- **Зіпсоване повідомлення відкидається**, а не повертається в чергу — інакше
  воно крутилося б вічно. Збій обробки (база недоступна) — повертається.

## Що блок публікує

| Подія | Коли | Хто слухає і навіщо |
|---|---|---|
| `vehicle.created` | додано автомобіль | `analytics` — автопарк |
| `vehicle.updated` | змінено номер, марку чи власника | `work-orders` — оновлює власну копію номера й марки |
| `vehicle.archived` | архівовано | `analytics` |
| `vehicle.mileage_recorded` | записано пробіг | `analytics` — пробіг між візитами; `notifications` — нагадування про ТО |

## Межі

**Держномер нормалізується.** Без пробілів і дефісів, у верхньому регістрі,
кириличні літери-двійники (А, В, Е, І, К, М, Н, О, Р, С, Т, Х) — латиницею.
Оператор набирає «аа 1234 вс», база бачить `AA1234BC`, і дубль ловиться.

**Унікальність — серед активних.** Номер і VIN не можуть повторюватись серед
неархівованих автомобілів. Номер проданого й архівованого авто може перейти на
нове. Помилка 409 каже, чий це автомобіль.

**Пробіг не зменшується.** Менше число — помилка введення або скручений
одометр, і в обох випадках людина має це побачити: 409, а не тихий запис.

**Архівування мʼяке.** Автомобіль зникає зі списків, але лишається доступним за
ідентифікатором — наряди на нього посилаються.

## Запуск

```bash
docker compose up -d postgres rabbitmq
cd services/vehicles
cp .env.example .env
uv sync --group dev
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8003
```

Без `RABBITMQ_URL` сервіс працює, але копія власника не оновлюється подіями.

## Перевірки

```bash
cd services/vehicles
uv run pytest         # 26 тестів: API, customers підмінений, обробник подій
uv run ruff check .
uv run mypy app

cd ../..
pnpm --filter @baymeister/module-vehicles typecheck
```

## Що лишилось зробити

- Сервісна книжка — чекає на `work-orders`: наряди по автомобілю.
- VIN-декодер (марка, модель, рік за VIN) — блок `integrations`.
- Список автомобілів на картці клієнта — екран `customers` читатиме
  `GET /vehicles?customer_id=…`.
